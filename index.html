GPU network

Stated plainly

A paid call is a USDG payment to the payee settled the x402 way: an EIP-3009 authorization used in the same transaction. Other USDG transfers to it are shown apart, not counted. Payments made with prepaid credits or other tokens are not visible here, so a network can serve more than Ruby sees. Some endpoints do not let a browser read them: paste the payee address then.

R21 · RUBY AGENT

Give it a task. It reads the chain for you.

Ruby Agent is an AI agent in your terminal. It takes a task about Robinhood Chain, calls Ruby's read-only tools one after another until it can answer, then writes the answer and every step it took as a note in your vault, so each number can be traced to the read behind it.

How it works
1 · TASKyou write what you want to know, in any language
2 · PLANthe model picks a Ruby tool and its inputs
3 · READthe tool reads Robinhood Chain; the result goes back to the model, up to 15 times
4 · NOTEthe answer, plus every tool call and its data, as Markdown in your vault
Run it

Node 18 or newer. Use your own OpenRouter key: create one free at openrouter.ai/keys. Free models need no credit.

export OPENROUTER_API_KEY=sk-or-… # macOS / Linux set OPENROUTER_API_KEY=sk-or-… # Windows CMD npx -y github:rubykit-star/ruby agent "is RUBY's liquidity locked, and who sold it today?"

--model picks any OpenRouter model (default openrouter/free) · --steps caps the tool calls (default 8, at most 15)

Playbooks · a report that writes itself

A playbook is a saved list of Ruby's read-only tools. No AI and no key needed: every number is a read. Each run writes a note and a "what changed since the last run" table: holders, top 10 share, price, curve progress or the locker's share, creator's holdings.

npx -y github:rubykit-star/ruby playbook token RUBY # one report now npx -y github:rubykit-star/ruby playbook token RUBY --every 24h # again every 24 hours npx -y github:rubykit-star/ruby playbook # list your playbooks

Any token works: playbook token 0x…. Make your own in ruby.json under "playbooks", as a list of tools such as ruby_lens_new or ruby_flow. Add --ai for a short summary by Ruby Agent with your own key. --every keeps running while the window is open; for a fixed time each day, use your computer's scheduler (Task Scheduler on Windows, cron on macOS and Linux).

Prefer the browser?

No terminal needed: AI Model lets a model call Ruby's tools right on this site, with your own OpenRouter key kept in your browser. The difference: answers there are not saved as notes in your vault.

R22 · RUBY LENS

Every new token. Under the lens.

Now on Robinhood Chain, Elysium and Solana. Ruby Lens reads the launchpad's own events and the token's contract, then shows the facts: who launched it, what the creator bought and sold, how far the bonding curve is from its target, who holds it, and, once it graduates, whether the liquidity is locked. From this browser, your terminal or your AI. Facts only, no score.

Check a token

The token's facts appear here: Sourcify, owner, launch and creator, bonding curve or locker, trading and holders, each with its link.

New launches

Open this page to read the latest launches.

In your terminal, or from your AI
npx -y github:rubykit-star/ruby lens # the latest launches npx -y github:rubykit-star/ruby lens 0x… # every fact about one token

Writes the same as a note in your vault. AI apps get it with ruby_lens_new and ruby_lens_check on the hosted MCP at ruby-mcp.vercel.app/mcp, and Ruby Agent uses them on its own.

Stated plainly

Launches are read from both Pons launchpad factories. Progress is the ETH in the curve against the target the launch event (or the curve) states; the curve's source is not verified on Sourcify, so check it against the launchpad's own page. Holders are rebuilt from every Transfer log; the curve, the pool manager, the locker and burn addresses are not counted as holders. On Elysium, the public RPC allows small windows only, so holders and trades are rebuilt for young tokens (about 1.5 hours) and the launcher's contracts are not verified on Sourcify. On Solana, names come from the token's metadata or, when it has none, from Jupiter's index, and the pump.fun bonding curve is read directly. Elysium and Solana answers come through Ruby's hosted MCP. No score, no rating, no price call: what you do with the facts is yours.

x402-style payments. As they settle.

A live feed of USDG transfer-by-signature on Robinhood Chain, the way x402 payments settle: who paid, who got paid, how much, and the transaction. Read straight from the chain, nothing signed.

What you are looking at

x402 payments in USDG settle with transferWithAuthorization (EIP-3009): the payer signs once, and USDG emits AuthorizationUsed when the transfer lands. Ruby lists every one of those on Robinhood Chain and pairs it with its transfer.

Not every EIP-3009 transfer is an x402 API call: wallets and apps use it for gasless transfers too. API calls are usually tiny, so use under 1 USDG to see payments that look like x402. A payer that is a contract signs through ERC-1271.

R6 · PRIVACY

Lock your notes. See your footprint.

Your research stays yours, encrypted on your machine. And a plain look at what your wallet already shows the world, so you can show less.

Lock your notes

Every note in the vault is encrypted with your password (AES-256-GCM, key from scrypt), on your own machine. Safe to keep in a cloud folder or in git. Ruby checks each file decrypts back to the same bytes before it removes the plain copy, and a wrong password changes nothing.

npx -y github:rubykit-star/ruby lock npx -y github:rubykit-star/ruby unlock

Lose the password and the notes cannot be opened. Nobody can reset it.

See your footprint

What anyone can already read about a wallet: who it moves tokens with, the hours it is active, what it holds and which approvals are still open. Gathered so you can see your own exposure, then act on it.

npx -y github:rubykit-star/ruby footprint 0x…your-wallet npx -y github:rubykit-star/ruby footprint 0x… --days 90
Local first

This site has no trackers and no analytics. Clip, Daily and Seal run in your browser and read the chain directly. Nothing is sent to a Ruby server, there isn't one.

Your RPC

Every read goes to a public Robinhood Chain RPC, which sees your IP. Use your own endpoint with RUBY_RPC.

What Ruby can't do

A public chain stays public. Ruby cannot hide transactions, and it will not mix funds. It helps you see what shows and keep your own notes private.

Ways to show less

Keep a separate wallet per purpose. Fund a new wallet from a source not linked to your main one, and don't send between them directly. Revoke approvals you no longer use.

R7 · SEAL

Prove a note. Without showing it.

Seal the SHA-256 of a note on Robinhood Chain from your own wallet. Later anyone can check the note is unchanged since that block. The only Ruby tool that writes, and it is simulated first.

SEAL A NOTE · CHECK A SEAL

Pick a note. Your browser hashes it (SHA-256); the note itself never leaves your computer. Then seal the hash from your wallet, or check an existing seal.

sha-256 –
connect a wallet to seal · 0 ETH to yourself, data = ruby-seal:hash · simulated on mainnet first
How it works

Your browser computes the note's SHA-256. A 0 ETH transaction from your wallet to itself carries "ruby-seal:" + that hash. The block time is the date.

Private by design

Only the hash goes on chain. Nobody can read the note from it, and change one character and the hash no longer matches.

In your terminal
ruby seal note.md ruby verify note.md 0x…tx

PROTOCOL · v0.1

Open rules. No Ruby required.

How Ruby writes notes, seals them and locks them, written down so any tool or AI can read Ruby notes and check Ruby seals on its own.

1 · Notes

A note is a UTF-8 Markdown file that starts with YAML frontmatter between --- lines. Values are JSON literals. Every note has type and tags; readers ignore keys they do not know. Every fact in the body links to where it can be checked. Facts, never scores.

2 · Seals

A seal proves a file existed, unchanged, at a block.

hash = sha256(file bytes) 64 lowercase hex tx = from: sealer to: sealer (same address) value: 0 data: utf8("ruby-seal:" + hash) chain: Robinhood Chain mainnet (4663)

Verify: 1. hash the file · 2. the receipt status is success · 3. the data, read as UTF-8, equals ruby-seal: + hash exactly · 4. the block time is the seal time, from is the sealer · 5. anything else is not a match. Writers simulate with eth_simulateV1 before the sealer signs.

Try it on the Seal page →

3 · Locked notes

A locked note is <name>.md.ruby, encrypted on the user's machine.

"RUBY1" 5 bytes salt 16 iv 12 tag 16 (GCM) cipher AES-256-GCM over the exact note bytes key scrypt(password, salt), N 2^15, r 8, p 1, 32 bytes

The writer checks the locked copy decrypts to the same bytes before removing the plain note. A wrong password or a changed file fails the GCM check.

5 · Principles
Read only

The only write is a seal, from the user's own wallet, after a simulation. Ruby never holds a key.

Facts, never scores

No ratings, predictions, or buy and sell advice. A link for every fact.

Local and plain

Notes stay on the user's machine as Markdown. No Ruby server receives them.

What Ruby does not do
No scores

It never rates a token, calls anything safe, or tells you to buy or sell. Facts with links only.

No keys

It never holds or asks for a private key or seed. The only write is a seal you send from your own wallet.

No server

Your notes stay in your vault. No Ruby server receives them, and nothing is tracked.

Limits, stated plainly: a seal proves a note is unchanged since a block, not that what it says is true. Ruby reads public data, so it cannot see anything the chain does not show.
